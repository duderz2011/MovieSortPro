# V3.1 — Unmatched movie routing

- Default-enabled setting: **Send unidentified films to unmatched**.
- After scan, any film without a confirmed provider match is routed to `<destination>/unmatched/<original filename>` in the preview and subsequent organise step.
- Applies to no-match, ambiguous, or provider-error results (not to a known film missing an optional sort field).
- When the app is in Copy mode, unmatched movies are **copied**; in Move mode they are **moved**. The global action always applies; this avoids unexpected data loss.
- Original filenames and extensions are retained, including when standard Rename is selected. Matching sidecars retain their original names.
- Report marks completed unidentified movie transfers `UNMATCHED` and counts them in the summary.
- Choosing the destination folder itself as the next source allows in-place reassignment once a valid match is available.
- Repeated runs detect already-correct paths or identical files to avoid duplicates.
- Unit tests in `test_unmatched.py`; GUI end-to-end tests in `gui_unmatched_test.py`.
- Preview/confirmation is required before any file changes.
